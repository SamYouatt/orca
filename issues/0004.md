# Harden issue CLI contracts and edge-case behavior

## What to build

Harden the completed `orca issue` workflow so its command contracts are reliable under error conditions and concurrent agent use. This slice should tighten output and error semantics, verify concurrency-sensitive ID allocation, and complete the integration coverage for the supported issue lifecycle.

## Acceptance criteria

- [ ] The final issue CLI contract is consistent across commands: `create` prints only the new ID, other successful mutations are silent, read commands honor their text/JSON contracts, and invalid operations return clear stderr text with non-zero exit codes.
- [ ] Concurrent issue creation remains safe per repository through transactional ID allocation and uniqueness guarantees, with regression coverage for contention-sensitive paths.
- [ ] The end-to-end issue workflow is covered by integration tests spanning creation, listing, showing, dependency edits, update semantics, filtering, and invalid-edge cases.
